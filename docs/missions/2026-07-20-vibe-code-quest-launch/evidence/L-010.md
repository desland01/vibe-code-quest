## 4. The failure — G-8

```
POST /api/guide  {"regionId":"databases","landmarkId":"sql","message":"…"}
→ HTTP 200
  {"kind":"offline",
   "message":"SQL databases store durable records in tables …",
   "banner":"The guide is offline — here's the canonical explanation"}
  latency 0.34 s
```

The guide returns the **canonical offline text, not model-generated text**. This is precisely
the state G-8 was written to detect, and precisely the state a visual-only pass would have
called a success.

### Diagnosis

Vercel runtime logs for that request:

```
POST /api/guide 200
  [analytics] guide_chat_message {"model":"offline","fallbackReason":"gateway_down"}
  [analytics] guide_unavailable_shown {"fallbackReason":"gateway_down"}
```

`gateway_down` has two possible sources in `src/server/guide.ts` — a failed usage reservation
(line 64) or the executor call itself (line 72). It is the second:

- `GET /api/guide` returns `{"allowed":true,"banner":"ok"}`, so `checkAccess` succeeded — the
  database is reachable and no cap is exhausted or zeroed. `reserveUsage` runs the same
  `decide()` logic, so the reservation is not what failed.
- The response came back in **0.34 s**. A real gateway call to a valid model takes far longer,
  and an unknown-model rejection still requires a network round trip. This request never
  touched the network.

The only path that returns `gateway_down` instantly without a network call is the credential
guard in `src/server/ai.ts`:

```ts
if (!params.transport && !hasGatewayCredentials()) return { kind: 'gateway_down' };
// hasGatewayCredentials() = AI_GATEWAY_API_KEY || VERCEL_OIDC_TOKEN
```

**Conclusion: the production runtime has neither `AI_GATEWAY_API_KEY` nor `VERCEL_OIDC_TOKEN`.**
`VERCEL_OIDC_TOKEN` is only injected when OIDC Federation is enabled on the project, so it is
evidently off here.

This is *not* a regression and not the invalid-model defect returning — L-009's model ids were
verified against the live gateway and `npm run check:models` passes. It is the one input the
mission never had: the credential G-6 assigned to the owner.

### Fix — either one works

**Option A (recommended) — set the key.** Add `AI_GATEWAY_API_KEY` for the **Production**
environment in the Vercel dashboard (Project → Settings → Environment Variables), then redeploy.

Use the dashboard rather than `vercel env add` piped from stdin: that path is known on this
machine to store an empty value, and `echo` adds a trailing newline. The dashboard avoids both.

**Option B — enable OIDC Federation** on the project (Settings → Security → OIDC Federation).
Vercel then injects `VERCEL_OIDC_TOKEN` automatically and no key is needed at all. L-009 made
the code accept this path.

Then redeploy and re-run the smoke:

```bash
vercel deploy --prod
PROD_URL=<new production URL> \
  node docs/missions/2026-07-20-vibe-code-quest-launch/scripts/l010-prod-smoke.mjs
```

A pass looks like `G-8 guide returns MODEL-GENERATED text — live model reply`.

### While re-running it — the deferred defect #9 decision

Record the observed latency of that first real guide turn. If turns approach or exceed **8 s**,
set `AI_REAL_MODEL_TIMEOUT_MS` above the default **and** raise `GuideChat`'s 12 000 ms client
abort to stay ahead of it. The coupling is documented at `src/server/ai.ts`. This is the
open follow-up from grill defect #9, deliberately left for real data rather than guessed.
