# Recovered intention — what the project was for, and where it drifted

Written 2026-08-03, after the owner said: *"whats being lost here is my original
intention which was I want to learn what all these things are and in a way that is
fun and works with the adhd brain."*

He is right. This file is the archaeology.

---

## 1. The original intention (office hours, 2026-05-03)

Source: `~/.gstack/projects/code-tutor/thebeast-greenfield-design-20260503-023821.md`
— "Design: vibe-tutor — A Map for Post-AI Builders", generated by `/office-hours`,
status APPROVED after two adversarial review passes, final score 9/10.

Verbatim from the problem statement:

> "This product is **NOT a code tutor**. It teaches no syntax. It is a **navigation
> course** — a map of the terrain, with an AI guide that personalizes the tour to
> who you are."

> "Vibe coders … are good at shipping but **blind to the developmental terrain
> underneath**. They can build a working prototype but don't know which database
> type their app actually needs, what server / hosting model to pick…"

> "**The user is the primary first user.**"

And the differentiator, stated three separate ways:

> "**The user-context onboarding is the differentiator** — who you are, what you
> build for, employee-vs-owner, interests. The map is the surface, **the user model
> is the moat**."

> Premise 2: "**Adaptive content rendering** … same canonical content, AI re-shapes
> it as overview / chat-lesson / quiz based on user profile."

> EUREKA: "Pre-AI tutorials shipped one format per concept because producing 3
> formats cost 3x. With LLMs the marginal cost is ~0. The 'pick a format'
> constraint dissolves. **This is the actual differentiator vs roadmap.sh /
> Brilliant / Boot.dev — they all chose ONE format. We can choose all three per
> user.**"

Premise 5: "**The map metaphor is load-bearing** — without it this becomes
'ChatGPT but for dev concepts', which is undifferentiated."

## 2. Where it drifted

| Original | What shipped |
|---|---|
| Navigation course — learn what the terrain IS | 144 identical multiple-choice worksheets |
| AI guide personalizes the tour to who you are | `GuideChat` is an optional side rail, and **REQ-026 requires every level to complete with the guide DISABLED** |
| Adaptive rendering: overview / chat-lesson / quiz **per user profile** | One fixed 8-beat sequence, identical for every player |
| The user model is the moat | There is no user model in the play loop |
| The user is the primary first user | Design was re-grounded on a corpus of *other people's* Reddit posts |

The differentiator was engineered out. Every mission made the guide more optional
and the sequence more fixed, for defensible individual reasons — offline play,
determinism, testability — and the cumulative result is a static worksheet with a
map bolted to the front.

## 3. The ADHD research was already in the repo, and the replan ignored it

Source: `docs/research/adhd-engagement-synthesis.md` (2026-07-19). Its honest
headline is that adult-ADHD product evidence barely exists, so these are *testable
priors*, not findings. They are still the best available and they are ours:

1. **Initiation beats motivation** — the first interaction must cost near-zero and
   pay off in seconds.
2. **Choice budget** — ≤3 options per beat, one focal action per screen.
3. **Time invisibility** — visible progress pips, "~3 min" expectations, never
   countdowns.
4. **Interruption is the default** — exact-beat resume is a correctness feature.
5. **Shame kills return** — punitive streaks, lost lives, red-flash errors trigger
   abandonment. Fail-soft retry only; progress never lost.
6. **Interest > importance** — relevance to **the founder's own project** sustains
   attention; every scenario a real decision, never trivia.

Top bounce risks named in the same document: text walls, spinner-first loops,
**punishment or loss states** ("one shame hit and the product is 'not for me'
forever"), choice paralysis on entry, no visible finish line.

## 4. Therefore: ALWAYS ALLOW is not adopted as ruled

The architect's ruling (`creative-vision.md`) is internally excellent and
well-evidenced. It is also aimed at the wrong target, and I briefed it that way —
my brief handed it the Reddit corpus and the honest audit, and never mentioned that
the primary user is the owner, that he wants to *learn what things are*, or that
the repo already holds ADHD design priors.

Two direct conflicts:

- Its core dramatic beat is an **incident**: you approved a catastrophe, your data
  is gone, now clean it up. That is a loss state, which this repo's own research
  names as a top-five bounce risk for this exact player.
- It **cuts the map and the guide** — the two things the original design calls
  load-bearing and "the moat".

What survives from it and should be carried into wayfinding, because it is right
regardless of direction:

- The honest audit: read-then-click is not a game; the current thing cannot be lost
  or played badly.
- **Prediction before execution** (Pan & Rickard, transfer d=.40) — generation, not
  recognition. Compatible with everything above and the single highest-evidence
  mechanic available.
- **An executable, visible model** beats a verbal description of one.
- Points/badges/streaks on unchanged content do not teach (Kapp's structural
  gamification; Mekler et al.; Hanus & Fox).
- Provenance discipline: content must trace to something real.

## 5. The question wayfinding has to answer

Not "what game do we build for vibe coders." It is:

> **What does Desmond do, for ten minutes, that leaves him actually understanding a
> piece of the dev terrain — where starting is frictionless, being wrong costs
> nothing, the thing being taught connects to what he is actually building, and it
> is genuinely fun rather than fun-shaped?**

Everything else — map, guide, levels, islands, arcade — is downstream of that.
