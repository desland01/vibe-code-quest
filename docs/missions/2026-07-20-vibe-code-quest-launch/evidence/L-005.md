## Design (locked from comps gate)

| Surface | Behavior |
|---|---|
| Ownership | Server progress `state.completed === true` only (returned PUT/GET). Never local reducer, localStorage, or outgoing payload. |
| Registry | 48 unique keepsakes (one per canonical landmark): id, name, 2-char sigil |
| Neon | **No new migration.** Ownership derives from existing `progress` rows. |
| Collectible grant | Static badge inside existing stamp moment. No third celebration animation. |
| Fresh stamp | Stamp-in animation + live `role=status` grant only after real stamp gesture this session. |
| Resume | Static stamp + static collectible. No live announcement. No stamp/glow replay. |
| Map glow surface | `SubMapScene` DOM landmark cards only (not Pixi overworld). |
| Glow motion | 1200ms ease-in-out × 3, then settled warm highlight via `onAnimationEnd`. |
| Glow markers | sessionStorage presentation hints; intersected with server-confirmed completed; TTL 30m; consume only on region overview. |
| Multi-marker | All unconsumed owned markers for the current region animate once (one glow per landmark budget). Cross-region markers preserved. |
| Shelf | Region overview only. 3-col desktop / 1-col mobile. Earned vs Open. Positive-only copy. Quiet-hide when unauthenticated or progress unavailable. |
| Color never sole signal | `Stamped` text + collectible name; `Open` / `Earned` labels. |
| Reduced-motion | Stamp + glow animation none; labels remain legible. |

Judge record: [`comp-judgement.md`](./comp-judgement.md) (comps gate PASS 2026-07-24).

### Deliberate deltas vs judge record (not drift)

1. Multi-marker glow animates **all** unconsumed region markers (not newest-only). Still one glow per landmark; better when several stamps land before map return.
2. Shelf renders on **region overview only**, not landmark detail (keeps lesson focus).
3. `BeatPlayer` remounts with `key={region/landmark}` to prevent cross-landmark state leak.
4. Stamp animation gated to fresh gesture (`stampFresh` class) so resume/reload stays static.
