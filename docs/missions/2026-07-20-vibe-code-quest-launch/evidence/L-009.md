## 1. Defect #1 confirmed against the live gateway

The grill claimed all three configured model ids were invalid. Re-verified today against the
public, no-auth `GET https://ai-gateway.vercel.sh/v1/models` (**306 models**):

| Configured id (before) | On the gateway? |
|---|---|
| `anthropic/claude-sonnet-4-5` | **NOT FOUND** |
| `anthropic/claude-haiku-4-5` | **NOT FOUND** |
| `anthropic/claude-opus-4-6` | **NOT FOUND** |

The gateway spells version numbers with **dots**: `anthropic/claude-haiku-4.5` and
`anthropic/claude-opus-4.6` both exist. Every id in the codebase used dashes.

**Consequence, now confirmed rather than suspected: the AI guide had never executed a real
request.** Each turn failed on unknown-model, fell through to an equally invalid fallback, and
landed in `gateway_down` → offline canonical text. The offline path is good enough that it
masked the defect completely.

## 3. Defect #1 made un-repeatable

New `scripts/check-gateway-models.mjs`, wired as `npm run check:models`. It reads the three
effective ids exactly as `ai.ts` does, fetches the public model list, prints `OK`/`UNKNOWN` per
id, suggests near-miss ids from the same provider when one is unknown, exits **1** on any
unknown id, and exits **0** with a "skipped: network unavailable" message when offline so it
never blocks a developer on a plane.

```
$ npm run check:models
executor: openai/gpt-5.6-luna OK
fallback: openai/gpt-5.4-nano OK
advisor:  openai/gpt-5.6-sol  OK
```

Plus pure unit regression tests in `src/__tests__/ai.test.ts`: every id matches
`/^[a-z0-9-]+\/[a-z0-9.-]+$/`, **no id may contain a digit-dash-digit sequence** (`/\d-\d/` —
the exact shape of this bug), and `AI_MODELS` has exactly the three non-empty keys.

## 4. A second, independent defect found in this slice — OIDC authentication

While verifying the credential guard, `src/server/ai.ts` line 99 read:

```ts
if (!params.transport && !process.env.AI_GATEWAY_API_KEY) return { kind: 'gateway_down' };
```

That treats "no API key" as "no gateway". It is wrong on Vercel. Per
<https://vercel.com/docs/ai-gateway/authentication-and-byok>, a deployment authenticates with
**either** an API key **or** the automatically-injected `VERCEL_OIDC_TOKEN`:

> ```ts
> // Automatically uses OIDC on Vercel, falls back to API key locally
> const apiKey = process.env.AI_GATEWAY_API_KEY || process.env.VERCEL_OIDC_TOKEN;
> ```

**This would have defeated the whole point of fixing the model ids.** A production deployment
without `AI_GATEWAY_API_KEY` would have short-circuited to `gateway_down` and served offline
text forever, even though the gateway would have authenticated fine through OIDC — and the G-8
criterion (a real model-generated guide turn on the production URL) would have failed for a
reason that had nothing to do with models. The AI SDK already handles the OIDC fallback; only
our own pre-check blocked it.

Fixed with one helper:

```ts
export function hasGatewayCredentials(): boolean {
  return Boolean(process.env.AI_GATEWAY_API_KEY || process.env.VERCEL_OIDC_TOKEN);
}
```

Control flow is otherwise unchanged: the `drill === 'force_5xx'` early return still comes first,
and an injected `transport` still bypasses the credential check entirely (tests and the drill
harness depend on that). Four new tests cover neither-set, key-only, **OIDC-only**, and
injected-transport-with-neither-set.

**Practical consequence for L-010:** the production guide may work with no owner-provided key at
all, through OIDC. That does not remove the owner's option to set a key — it removes the hard
dependency.

## 5. Defect #9 — the 8-second timeout

`REAL_MODEL_TIMEOUT_MS` was a hard-coded `8_000`. The grill flagged that a reasoning-heavy model
would routinely blow it and degrade silently.

There is a real coupling worth preserving: `GuideChat` aborts its fetch at **12 000 ms**, so the
server timeout must stay meaningfully below that or the browser gives up first and the user sees
a generic failure instead of the graceful canonical-text fallback the server would have returned.

**No new number was invented.** Real model latency cannot be measured here — there is no gateway
key in this environment — so guessing a constant would be speculation dressed as a fix. Instead
the value became configurable with the default unchanged:

```ts
const REAL_MODEL_TIMEOUT_MS =
  Number.isFinite(configured) && configured > 0 ? configured : 8_000;   // AI_REAL_MODEL_TIMEOUT_MS
```

A non-numeric, zero or negative env value falls back to 8 000 rather than to `NaN`. The
8 000 / 12 000 coupling is now stated in a comment above the constant, including the instruction
to raise the client abort alongside it.

**Deliberately left for L-010 to settle with real data:** measure actual `gpt-5.6-luna` latency
on the production smoke, then set `AI_REAL_MODEL_TIMEOUT_MS` if 8 s proves tight.
