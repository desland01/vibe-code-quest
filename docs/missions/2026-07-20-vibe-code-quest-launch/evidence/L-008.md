## 2. Self-host mode (A4.9) — measured before and after

A production server was started with `DATABASE_URL` unset and probed with a purpose-built
harness, [`scripts/l008-nodb-probe.mjs`](../scripts/l008-nodb-probe.mjs), which asserts each
surface and fails the process on any 5xx.


More of the app already worked than expected: the map, the landmark content, the Play surface

### How it works

One predicate, `src/server/hosting.ts`:

```ts
export function isHostedMode(): boolean {
  return Boolean(process.env.DATABASE_URL);
}
```

`process.env.DATABASE_URL` is now read in exactly two places: this function, and `src/lib/db.ts`
where it is the pool's connection string. The three pre-existing inline checks in
`app/api/leaderboard/route.ts` were switched to call it, with no behaviour change.

| Surface | Local-mode behaviour |
|---|---|
| `GET /api/session` | Issues the cookie, skips the `profiles` insert, returns `{ userId, hosted: false }` |
| `GET /api/progress` | `200 { items: [], xp: { total: 0 }, hosted: false }` |
| `PUT /api/progress` | Validates exactly as before, then **echoes the merged state back** without persisting |
| `POST /api/guide` | The existing offline-shaped response carrying the canonical definition |
| `POST /api/lesson` | `lessonFallback`, no database access |
| `POST /api/onboarding` | `200` with a completed state, so any client call closes cleanly |
| `POST /api/share` | `503 { error: 'Share links need a hosted database.' }` |
| OTP request / verify | `503 { error: 'Saving progress by email needs a hosted database.' }` |
| `/api/leaderboard` | Already guarded — empty board on GET, refuses writes (a self-host instance never writes the hosted board) |
| Landmark page | Both server-side reads now require `session && isHostedMode()` |

Client surfaces hidden when `session.hosted === false`: the XP HUD, the Quest board link, the
email save modal, the onboarding panel, and the share section. They are replaced by one line
(`data-testid="local-mode-note"`).

**The `PUT /api/progress` echo is a deliberate design decision.** `BeatPlayer` only grants a
collectible after the server response confirms `state.completed`. Returning `401`/`503` would
have left self-hosters able to play but never able to earn a stamp collectible. Echoing the
already-validated merged state keeps stamps, collectibles and the region glow working while
storing nothing server-side. It cannot be used to forge anything: there is no shared board in
local mode, and `PUT /api/leaderboard` refuses outright without a database.

### A regression this slice caused, caught, and fixed

Making `/api/session` succeed had a consequence: every `if (session) { …database read… }` branch
that had been silently skipped (because a self-hoster previously got no cookie at all) started
executing and failing. `GET /map/databases/sql?format=overview` went from 200 to **500**.

The probe caught it on the first re-run. Both reads in
`app/map/[region]/[landmark]/page.tsx` — the `depth_preference` default-format lookup and the
`progress` seed for `initialProgress`/`regionStampedCount` — now require `isHostedMode()` too,
and every other route that reads the database behind a session check was audited and guarded on
the same rule: **a valid session is no longer sufficient to justify a database read.**

## 7. NOT DONE — publishing the public GitHub repository

G-5 authorizes publishing everything with full history once the scan is clean. The scan **is**
clean, and the repository is packaged and ready. **The publish itself has not been performed.**

There is still no git remote — the repo is local-only, so L-008's publish step means creating
the GitHub repository from scratch and pushing 116 commits to it.

Publishing a repository publicly is irreversible in practice: once pushed and indexed, the full
history including every mission packet and the complete work ledger is public permanently, even
if the repo is later deleted. That is exactly the class of outward-facing action that needs the
owner's own go-ahead in the session where it happens, rather than an authorization inherited
from a document. It is recorded here as the owner's action, with everything else finished so it
is a single command.

**Owner action, when ready:**

```bash
cd /Users/thebeast/code-tutor
gh repo create vibe-code-quest --public --source=. --remote=origin --push
```

Two things worth knowing before running it, neither a blocker:

- The published history contains operational detail that is not secret but is
  reconnaissance-useful: Neon branch and endpoint identifiers, the Vercel project id, and ledger
  lines noting that a Gemini API key was once pasted into a chat transcript (and should be
  rotated). G-5 chose full-history publication knowingly; this is the concrete content of that
  choice.
